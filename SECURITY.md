# Безпека та конфіденційність — памятка для власника

Коротко: що вже захищено на рівні коду і що треба зробити на рівні домену та хостингу.

## Що вже налаштовано в проєкті

| Рівень | Що зроблено | Файл |
|---|---|---|
| HTTP-заголовки | CSP, HSTS, X-Frame-Options: DENY, nosniff, Referrer-Policy, Permissions-Policy | `_headers`, `vercel.json`, `.htaccess` |
| Зовнішні посилання | `rel="noopener noreferrer nofollow"` на всіх 8 зовнішніх лінках | `index.html`, `privacy.html` |
| Вбудована карта | Google Maps в iframe з `sandbox` і `referrerpolicy` | `index.html` |
| Скрипти | Лише власні файли, жодного inline-JS і жодного `eval` | `script.js` |
| Стилі | Лише зовнішній CSS, без inline-атрибутів `style` | `styles.css` |
| Телефони | Збираються з частин у `data-*` і рендеряться скриптом | `script.js` |
| Аналітика | Не підключена; `loadAnalytics()` запускається лише після згоди | `script.js` |
| Персональні дані | Форм немає, дані не збираються | `privacy.html` |

## 1. Поставте Cloudflare перед сайтом (безкоштовно)

- Додайте домен у Cloudflare, переведіть NS-записи на нього.
- Проксіювання (помаранчева хмарка) увімкнене — так ховається реальний IP сервера і вмикається захист від DDoS.
- Увімкніть **SSL/TLS → Full (strict)** і **Always Use HTTPS**.

## 2. Двофакторна автентифікація

- На **реєстраторі домену** — 2FA обов'язково (крадіжка домену = втрата бізнесу).
- На **хостингу / GitHub / Netlify** — 2FA для всіх, хто має доступ до публікації.
- Видаліть доступ у колишніх підрядників.

## 3. SSL-сертифікат

- На Cloudflare / Netlify / Vercel сертифікат оновлюється сам.
- На класичному хостингу — увімкніть автопродовження Let's Encrypt і перевірте, що нагадування йде на вашу пошту.

## 4. Резервні копії та оновлення

- Тримайте копію сайту (достатньо ZIP-архіву репозиторію) раз на місяць.
- Якщо хостинг з панеллю (cPanel) — увімкніть автобекапи.
- Раз на пів року перевіряйте, що ніхто сторонній не має доступу до DNS.

## Що робити перед публікацією

```bash
# 1. Перевірте заголовки після деплою (має бути 200 і всі заголовки)
curl -I https://ritmodelatina.com/

# 2. Перевірте CSP на сторінці
#    Відкрийте сайт → F12 → Console → не має бути "Refused to..."

# 3. Перевірте оцінку безпеки
#    https://securityheaders.com/?q=ritmodelatina.com
#    https://observatory.mozilla.org/analyze/ritmodelatina.com

# 4. Якщо колись зявиться Node-проєкт з package.json
npm audit
npm audit fix
# і не публікуйте source maps: GENERATE_SOURCEMAP=false
```

## Чого свідомо немає

- **SRI (integrity) для Google Fonts.** Google віддає різний CSS залежно від браузера,
  тому хеш неможливий — він зламав би шрифти. Правильне рішення: завантажити шрифти
  у власну теку `fonts/` і підключити локально. Тоді SRI стане доречним.
- **Обфускація телефонів «намертво».** Номери потрібні людям і пошуку; зараз вони
  збираються скриптом, що відсікає примітивних ботів, але не ламає доступність.
  Для повного захисту є `<noscript>` з номерами.
